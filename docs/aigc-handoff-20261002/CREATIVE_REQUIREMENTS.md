# BB箱子：荒诞 AIGC 短片创意规范与接手说明

整理日期：2026-10-02（北京时间）。用途：交给 MacBook 本地 Codex 接手，保留用户已提出的要求、否决意见、现有候选资产与未完成事项。

## 0. 接手先读：不能误解的五件事

1. 主项目是**真实摄影质感的荒诞短片系列**，画面核心是几个人一直在做播客。它不是常规访谈录像，也不是卡通宣传片。
2. 真实的「BB箱子」多人喜剧聊天节目与 AIGC 宣传短片有关联，但不是同一个产品。这个视频结尾招募的是**深圳南山、筹备中的多人喜剧聊天节目**。不要把课程、问答群或其他业务全塞进本期招募。
3. 结尾只是整支二十多秒短片的一部分。已经在结尾花费过多精力，不能再以结尾替代全片分镜、动作、节奏与音乐设计。
4. 已生成许多图片与若干视频样片，但**没有任何一支主片或学习复刻作品得到用户最终验收通过**。用户认可过某些图片的质感、部分场景和事件升级思路，不能扩大为全片批准。
5. 最新任务是整理并迁移现有项目和图片到 GitHub，让本地 Codex 接手。之前曾要求暂停当前制作，先学习原视频的导演和审美方法。本次迁移本身不等于授权直接付费生成、对外发布或擅自开启新方向。

## 1. 创作意图与观众

- 面向 Z 世代、乐子人，要有梗、意外、反差、故事性，并且愿意让人看完、在评论区互动。
- 内容同时展示团队的 AIGC、网页、PPT、代码与视觉制作能力，但不要把工具炫耀变成观众需要理解的主题。
- 荒诞来自「环境越来越离谱，几位嘉宾仍然正常聊天」的反差。
- 主体可以一直换。下一场景可以是另一批人、外星人、拟人地摆放的无生命物体，甚至特定虚构角色。选择第三方角色、商标和音乐前，必须考虑实际使用权限。
- 不需要把不同场景编成连续情节。各场景是独立小故事；整支片通过风格、节奏与播客形式统一。

## 2. 画幅、质感、人物与物理逻辑

### 用户确定的要求

- 全部画幅统一为 **3:4**。多人分镜拼图中，每个独立画格也应保留正确的 3:4 构图；拼图不是最终视频画幅。
- **真实摄影质感**：人物皮肤、衣服、材质、自然光、接触、重量和空间关系要可信。不要塑料感、廉价 CG 感或故事正文卡通化。
- 人类以亚洲面孔为主，不要每张都是外国人；年龄、性别与形象可以自然变化。
- 真实节目的常规设置是 **4–6 人**。AIGC 单场可出现 **3、4、5、6 位嘉宾**，可以非人，但不要一直固定三个人。
- 嘉宾数量按实际参与节目的人/物算，不能拿远处背景工人凑数。
- 可有桌子，也可没有；每人骑一头猪、坐在不同位置、站着、在车顶等都可以。麦克风、头戴收音等线索应让观众看得出他们正在做节目。
- 荒诞也要有规则：水下人物有头盔/氧气；鲨鱼不能在陆地无水呼吸，水体应覆盖鳃部；多人骑猪须多头猪或另有清楚合理的尺度设定；车顶开车需要可理解的操纵关系。
- 小陨石嘉宾可以是一块真实、坑坑洼洼的陨石，放在高脚凳上、前面一个麦克风即可。不要机械地加脸、手脚。

### 焦点与构图

- 主要笑点或环境事件必须清楚可读，不能用过浅景深把关键背景糊掉。
- 焦点该从谁转到谁、相机怎么移动、何时让观众发现秘密，都要有意图。
- 不是禁止全部虚化，而是禁止把应被看懂的东西处理得看不清。
- 人物、麦克风、道具与事件要构成可信空间。不能为冲击力牺牲肢体、支撑与碰撞逻辑。

## 3. 分镜与动作规则

### 同一场景内

- 尽量保持一个连续镜头，**不要反复硬切特写**。
- 可以突然放大、拉远、移动、旋转、焦点转移；必须预先决定路径和揭示效果。
- 主要动态来自环境与事件，不能只让主持人夸张表演、乱动或惊讶。
- 嘉宾也不是一动不动的蜡像：正常说话、轻微姿态变化、随载具运动的身体反馈都需要合理。
- 指令详细程度有优先级：镜头轨迹、焦点切换、核心动作、事件如何升级写清楚；不要逐条指挥章鱼每只触手每一下怎么打鼓，分散模型注意力。

### 场景之间

- 可以直接硬切；人物和场景可以完全更换，没有连续剧情或同一阵容的义务。
- 前三秒尤其重要，开场要有冲击与节奏。
- 每段时长不必一致。不要统一每场三秒/四秒导致机械工整。
- 不要所有小故事都是「静态画面→突然有个东西冲出来」。需混用持续错位、秘密揭露、身份反差、道具用途错误、环境持续失控、规模升级等不同冲突。
- 每一场要有可以看到的发展，而不只是奇怪场景的静态展示。
- 场景变化、鼓点、音效和动作重音必须共同设计，不能先随便剪图再铺音乐。

## 4. 用户手写笔记：已纠正的场景库

以下是创意库，不等于全部必须放进这一期，也不是已批准的最终顺序。

1. 街道突然洪水，有人在冲浪。
2. 草原骑猪，几个人分别骑不同的猪、拿着麦克风聊天。
3. 鲨鱼在陆地的荒诞节目场景，必须有供其呼吸的水环境；具体穿着与容器仍可优化。
4. 背景是办公室，大家穿白大褂而非西装，形成精神病院式错位感。
5. 地铁里有人戴拳击手套打拳击。
6. 「照相机」后有人手忙脚乱地画画，表面帮人拍照，实际靠手绘。必须让观众读懂前台假摄影与后台手绘的关系。
7. 街道上几个人骑巨大的乌龟。
8. 人坐在车顶上开车。
9. 工厂流水线上，清朝士兵在组装马车。
10. 录音棚有架子鼓；超大头章鱼戴着拳击手套打鼓，**不是用鼓槌**。
11. 浑身肌肉的老太太与成年眼镜男打拳击。

另有火山、男厕所小便池、海底、外太空等播客背景构想。飞机从河中飞出、电锯剪头等是用户从对标视频举出的冲击力参考，不能自动当成我们已定分镜。

## 5. D3 全片候选顺序：可接着审，不是锁定版

已有七场、约 20 秒正文的导演候选：

- 0.0–2.4 秒：章鱼录音棚，6 位嘉宾
- 2.4–4.4 秒：鲨鱼，4 位嘉宾
- 4.4–8.2 秒：手绘假摄影，5 位嘉宾
- 8.2–10.9 秒：清朝流水线，3 位嘉宾
- 10.9–13.6 秒：拳击馆，4 位嘉宾
- 13.6–16.6 秒：车顶开车，3 位嘉宾
- 16.6–20.0 秒：骑猪，3 位嘉宾；候选出现潜艇/地面变化的升级事件
- 后接约 5 秒结尾，具体时长和画面尚待改进

这套顺序、每段秒数、20+5 秒结构都是工作候选。用户从未要求精确固定为这些数字。最后连续三人场景偏多，应在全片审查时判断是否符合「不要总是三人」。潜艇升级是候选设计，不能说是手写原始构想。

## 6. 结尾：必须按层级和节奏设计

### 核心转场，用户明确画过

1. 最后一段故事素材仍在播放时，BB箱子 Logo 浮在画面上。
2. Logo 不消失，也不突然换位置或大小，把 **Logo 下方的故事素材切换成黑色**。
3. 此时 Logo 仍在；后续信息如何出现、切换和结束，需要参考原片继续设计。

Logo 必须保持的规则针对「故事底图→黑底」这个交接段，**不是要求之后所有信息页永远保留完全不动的 Logo**。不要增加用户没要求的死规则。

### 风格与 Logo

- 酷、真实 AIGC 风格配套，不要卡通片尾、廉价模板招聘海报或普通静态文字卡。
- 先查看 BB箱子原 Logo，再考虑改造。原形象包含长耳兔、黄色安全帽、扳手、蓝色箱子；有些头像带 Bono 铭牌，网站版本不一定带。
- 用户允许改造兔子，甚至只保留「BB箱子」字标。不是必须死守原插画，也不是可以完全另起一个不相关电竞标志。
- 不要出现真实团队成员拍摄画面，避免标准化制作依赖真人出镜。
- 信息转场需要设计和声画配合，不能把几张图片直接机械剪在一起。
- 字体必须与整体视觉统一、可读、有气质，不能随手用难看的默认字。

### 本期要传达的信息

- BB箱子是什么：真实的多人聊天喜剧节目，筹备/招募中；只写几个抽象口号不足以让人理解。
- 地点：深圳南山。
- 招募聊天搭子、制作伙伴等；岗位细项需要对照项目资料确认，不要凭空追加承诺或待遇。
- 可用「全网同名」等入口信息；不要把所有平台名字挤到看不清。
- 用户此前让用知名节目降低理解成本，后来明确改为 **不能直接写对标节目的名称**；可以通过视觉/访谈形式暗示。最新禁令优先。
- 展示制作能力应自然、不显摆。不要直接写「Codex 制作」或长篇解释自己用了什么工具。
- 最后一张可以自然集合实际用到的工具 Logo：OpenAI、Codex、GitHub、Claude Code 等是用户提及的候选。必须核实本片实际工具链，不能把没使用的工具写成制作事实，也不能暗示官方赞助。
- 用户后来明确要求去掉底部 Reference 和被参考视频的 Logo。**成片不展示该 Reference/来源 Logo**；制作档案仍保留可追溯来源。其他必须的版权署名应先核实，不能通过删字掩盖授权义务。

### 时长与安全区

- 全片才二十多秒，不接受 28 秒的片尾。
- 前一个方案节目页停留过长、信息太少，用户要求增加有意义的镜头/信息变化；不要单纯延长空卡片。
- 只对片尾重要 Logo、招募文字、入口考虑抖音 UI 遮挡。正文可使用全画幅，装饰可以延伸至遮挡区域。
- 既有 x60–536 / y133–720 等安全区数据只是旧界面示例的临时缓冲，不是官方固定通用参数。必须在目标比例、真实播放界面和小屏观看尺度下复查。

## 7. 音乐与声音

- 需要躁、抓人、鼓点密集、节奏强的音乐，用户倾向 hip-hop/rap，有人声更好。
- 人声并非绝对硬性条件；如果无人声，依旧必须找到足够带感的声画组织方式。
- 音效与动作、转场、视觉重音共同编排；有明确必要的环境音/特殊音效才写入生成提示词，避免无用细节淹没重点。
- 先分析对标的实际音乐、音效和节奏，不要靠「看了波形」冒充听过。
- 既有合成音乐和 D4 鼓点被否决；D5r1 采用真实鼓样，但未完成可验证的主观听审，不等于已经解决。
- 对标中的 N.W.A 等商业音乐没有因为可下载就自动获得再使用许可。正式公开版本应核对音乐/样本许可。

## 8. 视频生成与成本策略

用户希望等分镜明确后再提供视频 API。

- 如选定服务支持首尾帧固定，尽量合理合并多个场景生成，再本地剪掉坏段，以后续生成素材替换，以节省费用。
- 不要未经验证就承诺能一次精确生成全片，或能严格遵循「第几秒发生什么」。
- 必须针对**实际供应商、模型版本、国内/国外入口、检查日期**记录：最短/最长生成时长、比例、首尾帧、多人/人像上传限制、声音能力、参考视频能力、价格和调用方式。
- 同一服务的不同入口可能不同；网页功能不自动等于 API 功能。
- 镜头节奏能在后期剪辑中校准，模型秒级指令只是待验证能力。
- 不能为了绕过规则上传禁止的人像或假设所有人物照片都可用。
- 目前没有可证明完成的连续 AIGC 正文视频；图片平移、静态图拼片和图形片尾不等于正文镜头动作已完成。
- 还未取得明确的付费视频服务、API 与预算授权。迁移资料不自动授权购买、付费生成或向第三方服务上传素材。

## 10. 用户反复否决的模式：审片时逐条检查

- 「懂了」之后做出的东西仍和对标质感完全不同。
- 只做一张大图，不能高效审全片；用户希望适度合并场景/首尾帧到一张分镜图。
- 一直三位嘉宾、全是外国脸；多人挤在一头猪上等不合理设置。
- 塑料感、卡通化、焦点错误、主要背景笑点不可见。
- 一个场景切过多特写；主体戏太多，背景事件不够。
- 每场都「突然冲出一个东西」，事件套路单一。
- 只有好看的静态场景，没有故事、动作、发展与反差。
- 平均分配片段长度，没有前后三秒和整支片的节奏意识。
- 结尾像普通招聘海报；Logo 丑、与节目风格不搭；文字太少看不懂，或瞬间塞太多读不完。
- 直接写知名对标节目名字；把来源 Logo 放进成片；直接写「Codex 制作」而缺乏自然设计。
- 结尾比正文还长；只单独优化片尾不看全片。
- 音乐不躁、没有重音组织，音效与画面脱节。
- 复刻只做到技术结构相似，没有原片的审美、分镜、脚本、声画节奏。
- 只报告技术参数、文档页数、跑通渲染，拿不出完整可看的视频。
- 停停做做、不主动推进，需要用户反复催；缺乏阶段结果和真实障碍反馈。
- 用新创意小实验代替已交代的原片学习复刻。

## 11. 长期学习线：与本期制作分开

用户要求学习完整创作流程，而不是只复刻代码或逐帧临摹：

1. 从短提示词如何选择主题、创作主张和意外点。
2. 如何调研并选择真实图片、生成图、SVG、Canvas、3D、网页动画、AE 等合适媒介。
3. 如何写脚本、组织分镜、控制注意力与信息揭示。
4. 美术系统：字、色、材质、构图、空间和视觉符号如何统一。
5. 时间设计：停顿、爆发、重复、变化、转场动机、音乐与音效重音。
6. 执行管线、预览、审片、批评与迭代到交付。

每条结论应能对应原片时间点、观察证据、自己复刻的差距与改进结果。将作者自述、可见代码/公开流程、自己的推断分开；成片漂亮不能证明作者只用一句提示词，也不能证明某个模型有未公开的特殊工作流。

## 13. 接手后的检查顺序与验收

1. 对照迁移资产清单检查每张图片和每份源文件是否真的存在、可打开，历史废案与当前候选分开。

6. 生成、剪辑、声画、色彩与片尾一起审，完整播放并在手机尺度检查安全区。不能只看接触表、波形或渲染日志。
