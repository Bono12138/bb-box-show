# 内容怎样从飞书到网站

当前采用人工确认后的单向发布。飞书保存业务与协作记录；网站使用独立的公开内容文件。

1. 在飞书起草，给记录稳定编号，写明来源、日期、状态和负责人。
2. 确认公开范围，需要本人许可的内容先取得许可。
3. 单独整理公开正文，移除联系方式、内部链接、合同、授权原件、凭证和秘密。
4. 按 `content/articles.json` 更新文章，或使用受限导入工具。
5. 检查与构建后，实际查看正文、搜索、关联链接和手机断行。
6. 提交到 GitHub。Actions 成功后打开真实网址读回内容。
7. 回填飞书的发布链接、时间、版本和后续观察。

导入工具只接收单篇已审阅公开对象，默认仅检查：

```sh
node scripts/import-public.mjs /绝对路径/公开资料.json
node scripts/import-public.mjs /绝对路径/公开资料.json --apply
```

格式：`{ "approval": { "approvedBy": "实际审阅人", "approvedAt": "ISO 时间", "scope": "public" }, "article": { ... } }`。未知字段会拒绝；标记不代替人工核实，不可伪填批准人。稳定编号不变时更新文章，正文、搜索和关联项会随构建一起更新。

## 微信与表单

获得 Bono 同意公开的二维码后，保存到 `public/assets/`，在 `content/connections.json` 设置站内 `wechatQr` 路径和 `wechatId`。页面下方直接显示二维码与可复制微信号。未提供时保持 null。

表单分享 URL 可以公开，管理地址和访问令牌不能加入配置。替换表单须重新检查匿名访问、必填错误、提交和后台收件，再设置 `verified: true`。

隐藏字段不提供权限隔离。邀请伙伴时，先确定其所需权限；敏感资料不随协作台开放。

## 发布失败与更正

构建失败时，现有线上版本仍保留。按 Actions 报错修复，不强推或清空仓库。内容更正使用新提交，保留来源与变更记录。

若发生敏感资料泄露，先停止传播并联系平台处理历史与缓存。只改当前页面不能证明外部副本已清除。
